# Research edition interface (#57 → #58)

`python site/build.py` regenerates **factual drafts**, using `research/editions.yaml` archive start keys. The existing scheduled refresh/news deployments already run this build; no additional scheduler or data-commit mechanism is needed. Completed Monday–Sunday weeks and calendar months use Beijing end-of-day cutoffs. Stable routes are `/zh|en/research.html` and `/zh|en/macro-{weekly|monthly}-{period-key}.html`. `/memo.html` remains the prior deep dive. `data/research/index.json` lists editions; each ID has a matching JSON object.

`site/research_editions.py` owns generation and locale projection. The neutral object contains edition ID/type, period start/end, inclusive `as_of`, actual `generated_at`, review status, approval metadata, prior document reference, selected factual changes, interpreted charts, observation references, provenance, existing policy context, refresh record references and verified-calendar watch-next. #58 may consume `model['research_editions']` and `edition_context(edition, View)`; it must not infer approval from successful generation. The shared `_research.html` macros render cards/charts.

All current editions are `review_status=draft`, `signer=null`, `approved_at=null`, `thesis_delta=pending_analyst`. There is deliberately no approval command. #52 owns signed decisions; no signer is inferred from a baseline file, Git author, mechanical state or draft generation. The existing frozen prior is linked separately. A later approval integration must reference #52's actual accepted artifact and authenticity boundary, not relabel a draft automatically.

Numbers and adjacent-period differences come from public observation rows through the existing as-of/source/chart helpers. The selected indicators test price transmission, domestic-demand breadth and property drag; money is a supplementary cross-check. The short lead is conditionally chosen from those actual observations; all economic explanation is visibly draft. No LLM, numeric prose authored by a model, new provider or paid feed is involved.

A report is a **retrospective reconstruction generated now**, not proof of timely historical publication. Already captured public releases may fill a point not held at the historical cutoff, using the existing public as-of rule point by point. Each capture time and limitation is exported/displayed; availability with unknown official release date uses retrieval time. Vintages captured after generation, private/non-redistributable, suspect and caliber-break rows are excluded. Only adjacent reference periods receive a numeric difference. The calendar includes only entries verified by the cutoff. Policy context uses existing curated source-linked records and never becomes a new approved judgment.

The first Weekly (`2026-W45`, Nov 2–8 BJT) has no newly available observations among the selected indicators: it says so explicitly and carries forward charts. The first Monthly (`2026-10`) contains real price/order/activity evidence. Both contain five historical charts plus the money cross-check, competing explanation, watch-next, source links and raw observation lineage. Missing GDP release timing and unsupported market conclusions are disclosed rather than filled. Draft interpretation and any thesis change remain pending genuine analyst review.

Validation: targeted real-data chain and bad-input boundary, BJT period rollover, normal tests, public E0–E5 gate, static build, internal link/fragment scan and desktop/mobile zh/en light-theme inspection (including OS dark preference). Preview URL and verified head are recorded on the PR after deployment.

## Research inputs and series continuity (W4, Issue #69)

Each edition now carries `research_inputs`: up to six material leads (`research_needed`/`monitor`, never `irrelevant` or a `repetition_of`) from the committed #56 bundles under `research/cases/cn-nominal/inputs/`, read with `cnmacro.research_inputs.load_bundle`/`material_items`. Only bundles whose `as_of` is at or before generation are read; an invalid bundle is skipped whole. A lead belongs to the period in which it was **published** (BJT start to the inclusive cutoff); when it was captured after the cutoff it is flagged `retrospective`, the same rule already used for observations. Ordering is research materiality (triage, then official release → first-party policy → media), never popularity. Exported fields are title, link, publisher, publish/capture times, H-links and mechanism, and observation refs only when that observation was itself available by the cutoff. Excerpts are not republished.

`previous_edition`/`next_edition` link editions of the same type, and `since_previous` lists each selected indicator whose latest reference period moved since the previous edition (from/to period and value, both from the editions' own observation rows). The first edition of a series says so. When no selected indicator printed in the period, the lead states that plainly and counts the research-needed leads instead of repeating the prior headline. All of this remains draft: no thesis, probability, signer or approval changes.

New series run automatically: the next scheduled build after Monday 00:00 BJT adds the completed week (e.g. `2026-W46`, Nov 9–15, containing the Oct CPI/PPI print), and after the 1st adds the completed month. Leads exist only for days covered by a committed bundle; bundle generation itself is #56's command and is not scheduled here.
